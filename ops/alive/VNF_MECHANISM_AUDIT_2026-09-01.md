## 0. What a "seed" is, and where it comes from

Seeds live in the `benchmark_calibrations` table: one row per calibrated survey question with `question_text`, `embedding` (gte-small 384-d), `target_by_group` (per-country/cohort YES shares), `solved_weights` (8-9 signed trait weights back-solved by `solve-inverse-weights`), `solved_baseline`, `residual_rms`, `confidence`, `source_instrument` ('GOQA'|'WVS'|'GSS'|'Pew'|'Gallup'|'PRRI'|'live_grounding'|…), and a Postgres-GENERATED `holdout` flag (~15% by md5 of question_text). Ingestion is `supabase/functions/wvs-batch/index.ts` and `supabase/functions/goqa-batch/index.ts` — both are chunked fan-outs that POST each flattened seed to `solve-inverse-weights` with `persist:true, confidence:"high"` and log to `calibration_runs`. GOQA rows are binarized by `defaultYesIndices` (`/(strongly )?agree|favor|approve|good|yes|support|trust/` picks YES options; else first half of options), require ≥3 country groups (goqa-batch/index.ts:37-57). Nearest-neighbour retrieval is the `match_benchmark` RPC (embedding cosine over this corpus).

## 1. The exact fallback ladder (ground-question)

`supabase/functions/ground-question/index.ts` is the single grounding resolver every door calls. Thresholds (lines 38-39):

```
const SIM_HIGH = 0.85;
const SIM_ANCHOR = 0.65;
```

Pipeline per question: canonicalize (gemini-2.5-flash-lite) → `stripInstrumentPreamble` → gteEmbed → `match_benchmark(p_match_count:8, p_min_similarity:0.65, p_include_low:true)` in parallel with entity extraction + **adversarial two-pass web grounding** (3 YES-supporting + 3 NO-supporting atomic facts, interleaved, max 8; lines 258-291), plus a future-event date gate that drops facts pairing a future date with an outcome verb (`OUTCOME_VERB_RE`, lines 342-360) and clamps baseline to `FUTURE_BASELINE_CAP = 0.6` for "will …?" questions.

Retrieval re-ranking before the ladder: instrument preference (US-framing → Pew/Gallup/GSS/PRRI, multi-country → WVS/GOQA, promoted only within Δsim ≤ 0.05), richness tiebreaker (more `target_by_group` entries wins within the ≥0.85 band), and a **rephrase probe** whenever topSim < 0.95: `rephraseSurveyQueries` (Sonnet) rewrites into 3 survey-organization queries, each re-probed against `match_benchmark`, merged best-per-id.

Every retrieved anchor is then classified by `classifyAnchorPole` (Sonnet, fail-closed to `unrelated`) plus a regex `detectStemCollision` guard (same stem family, different object → forced `different_question`). The ladder, first rung that fires wins:

- **PATH A `survey-matched`** — `topSim ≥ 0.85 && (topSim ≥ 0.95 || confidence==='high') && anchor_pole==='same_pole'`: blind-copy the seed's `solved_weights` + `solved_baseline` (lines 750-798).
- **PATH B `reference-anchored`** — same_pole at moderate sim, or opposite_pole at ANY sim with `baseline_stance = -solved_baseline` (`anchor_baseline_inverted`, lines 799-821).
- **PATH B-dampened `reference-anchored-dampened`** — `different_question`/`related_dimension`: weights × `min(cap, (sim − 0.50)/0.35 × cap)` with cap 0.30 (different_question, hard cap after the "rubber stamp" fix) or 0.65 (related_dimension). Flat-output escalation: if `|baseline|·0.5 + mag·0.5 < 0.10` (answer would land within ±10pt of a coin flip) the dampened anchor is discarded and it falls to Path D (lines 822-895).
- **PATH D `live-grounded`** — `_shared/live_grounding.ts`: Sonnet (`claude-sonnet-4-5`) with the native `web_search_20250305` tool (max 3 searches) hunts for real published polling; results must match `CREDIBLE_ORG_RX` (Pew|Gallup|Ipsos|YouGov|Eurobarometer|…); country findings averaged into `target_by_group` plus left/centrist/right political cohorts at the aggregate; **flat-scrape gate** rejects spread < 0.04 or <2 distinct values ("solver would fit noise"); then `solve-inverse-weights` (persist:false), rejected if `condition_number > 20000`; on success the result is **persisted as a new seed** (`source_instrument='live_grounding'`, confidence='medium', 7-day freshness, refreshed by `refresh-live-seeds` cron) — so a novel question that live-grounds becomes a seed for its neighbours. Excluded from gate/holdout/offset evaluators by instrument filter.
- **PATH C `forward-estimate`** — last resort: `mapTraitStanceSonnet` (`_shared/trait_stance.ts:76-175`) asks Sonnet for 9 signed trait→YES weights ("POSITIVE = high values of this trait push the agent toward YES … Notice fear FLIPS sign between the two questions") plus a `baseline_stance` prior in [-1,+1] ("-0.30 ≈ 35% YES") derived from the adversarial facts.
- **No-signal recovery** — if `weight_magnitude < 1e-4` (`isNoSignal`, `_shared/grounding_recovery.ts`), ground-question recursively re-calls itself up to twice with fixed reframings (`noSignalRetryPrompt`, then `generalizedRetryPrompt` which strips locality: "people in Milan" → generic attitude), cached under the ORIGINAL proposition (`cache_as`) so both transports see one solve (index.ts:1139-1170).

**Status contract** (`_shared/prediction_status.ts`): `survey-matched`/`live-grounded` → **grounded**; `reference-anchored*` → **seeded**; `forward-estimate` or magnitude < 1e-4 → **abstained** ("Callers must NOT emit a probability. Previously this path silently produced a zero-force run that collapsed to ~50% and was reported as a confident prediction"). So the honest ladder is: **seeded-exact → seeded-neighbour (poled/dampened) → live web survey → LLM forward estimate → abstain**, with forward-estimate itself downgraded to abstention unless rescued (next section).

## 2. Publishability gating of the no-seed result

`evaluateGroundingGate` (`_shared/grounding_recovery.ts:200-266`) is the ONE shared gate (both `resonate/index.ts:535` — persisted door, and `_shared/globe.ts:440` — live API door):
- A **measured anchor** near-identical to the question (`publishableOnMeasuredAnchor`, sim ≥ `MEASURED_BIND_SIM` from engine_args) publishes even on a zero-force solve — "the percentage IS the evidence."
- transport failure / zero force on an opinion → abstain.
- `anchor_pole==='unrelated'` is fatal for an **opinion** ("the question claims to report what people were measured to think") but expected for a **forecast/forks/personal/explainer** shape and for attitude propositions — those publish as mode `exploratory`.
- `forward-estimate` publishes as `exploratory` only when the premise evidence bundle qualified (≥3 facts, ≥1 source); else `forward_estimate_without_evidence` abstention.
- Abstentions are persisted as structured objects: "Earth-1 found no relevant factual, survey, or market anchor, so it did not manufacture a probability from population traits." (resonate/index.ts:559).

**The published-number anchor ladder** (`_shared/anchor_ladder.ts` + `_shared/globe.ts:600-633`): "there is ALWAYS an anchor" — measured → market → evidence → llm_prior. Rung 1 is `_shared/measured_anchor.ts` (its own coverage ladder: exact `benchmark_calibrations` → exact `goqa_staging` → vector `match_benchmark` ≥ 0.78 → Jaccard ≥ 0.5 lexical over ≤600 goqa_staging rows; population-weighted across `country_XX` via `census_country_targets`, ≥3 groups). Rung 2 is a live prediction-market price (soft anchor; on forecast shapes money outranks and demotes/displaces survey anchors — globe.ts:556-598). Rungs 3-4 are `resolvePriorAnchor`: Sonnet estimates a YES share from the retrieved facts ("Never return 0.5 as a way of avoiding a judgement"), tiered `evidence` (grounded_in_facts, conf ≤ 0.5) vs `llm_prior` (conf ≤ 0.4, floor 0.2, shrinks with band width); always SOFT, always stamped with provenance ("no survey, market or factual record prices this proposition. Treat as the weakest anchor."). Purpose stated in globe.ts:606: an unanchored run "parks on the product slope's prior and lands in the 45–55 band, which is the failure this ladder exists to remove." There is also `inferForces` (globe.ts:332-358, `model-inferred` regime) for Globe reactions when grounding is empty — explicitly not used by benchmarks/prediction workers.

## 3. The per-force relevance gate (news→question injection, not answering)

`_shared/relevance_gate.ts` is the no-seed contract for *signal injection* (used by `inform-agents/index.ts:220`, planned for the field receiver): `R_{q,f} = |solved_weight_f| / max_f|solved_weight_f|` from the nearest seed via `match_benchmark` at `GATE_MIN_SIMILARITY = 0.80`, sharpened (`raw < 0.35 → 0`, else `raw^2.0`), `D = sign(w)`. Hard contract: "NO seed match => R = 0 for every force. A signal that cannot be tied to a solved force decomposition must not move anything. Silence beats a uniform offset." Combined with topical cosine rescaled over [0.62, 0.82] ("gte-small puts unrelated short texts around 0.60") and event force amplitudes: `salience = topical × Σ A_f·R_f / Σ A_f`; below `min_salience = 0.15` or with no seed, injection is `gated_out` and only logged (`inform_force_activations`). Activation formula: `λ·A_f·R_f·D_f`, λ = 0.15·topical. So for a question with no seed, world events cannot move agents at all — by design.

## 2. Market anchoring at answer time (Polymarket + Kalshi, no keys)

Files: `_shared/market_anchor.ts` (619 lines), `_shared/polymarket-tool.ts`, `api-market-anchor/index.ts`, wired in `api-globe-ask/index.ts` and `resonate/index.ts`.

  - Kalshi: `https://api.elections.kalshi.com/v1/search/series?query=…` then `…/trade-api/v2/markets?event_ticker=…&limit=200`; prices are bid/ask midpoints (`(yes_bid+yes_ask)/2`, fallback last price).
- Matching (the load-bearing part, `classifyMatch`, market-matcher version `market-matcher-2026-08-10.1`): discovery floor `match_score ≥ 0.45` token overlap divided by the LARGER set ("Dividing by the smaller set lets a two-word book title ('Donald Trump') score 1.0 … which is how an opinion read ends up anchored to a UFC-attendance market"). Hard disqualifiers → state `related` (context only, never compared): subject overlap < 0.45, year mismatch, jurisdiction conflict (regex table US/UK/EU/FR/DE/IN/BR), already-past resolution, conditional-vs-not. Soft caveats → `compatible`: liquidity < $5,000 (`MIN_LIQUIDITY_USD`), unknown horizon, subject < 0.7. Legally impossible outcomes are struck and the book renormalized (`applyOutcomeConstraints` via `premise_rules.ts:validateOutcomes` — "a price on a legally impossible outcome is a statement about the contract's wording").
- Blending formula (the actual number-level fusion): `marketYesProbability()` returns the Yes price only for a binary exact/compatible primary book. `api-globe-ask` passes it as `engineOpts.marketAnchor` into `runEngine` (`_shared/globe.ts:563-605`):
  - On forecast shape a measured survey anchor is DEMOTED ("money outranks a survey anchor … a survey measures belief today; a forecast asks about the world"), and the market price becomes the soft conformity target: `anchor.conformity_anchor = mkt; anchor.baseline_confidence = max(…, 0.5); hard_anchor = false`.
  - Inside the vote SQL (`compute_civilization_answer*`, e.g. migration `20260729145136…sql:248-258`): `v_conf_target := COALESCE(p_conformity_anchor, v_post_cap_yes_pct); v_eff_lambda := 0.5 * baseline_confidence (when anchored); adj_yes_score = clamp01(yes_score + (1 − openness_trait) × (conf_target − yes_score) × eff_lambda)`, then re-vote through the same RNG sigmoid `rng < 1/(1+exp(−k·(adj−0.5)))`. So a market price pulls each agent toward it proportionally to their conformity (1 − openness), with an effective λ ≈ 0.25; it never hard-pins.
  - Timing: fired in parallel with the premise gate; the engine waits max 8 s for the book (`Promise.race … setTimeout(8_000)`) — "Never let the book delay the simulation".

Divergence is the signal, not an error."

## Leakage prevention into benchmarks (what's real, what's porous)

Defenses that exist:
- Live seeds carry `confidence='medium'` and are excluded BY FILTER from every evaluator: `evaluate-production-gate` (`.eq("holdout", true) … .neq("source_instrument","live_grounding")`, line ~423-428), `evaluate-holdout` (line 172-175: "live-grounded seeds never enter holdout evaluation (medium-confidence, web-sourced; not spot-checked)"), `update-culture-offsets` (non-holdout residuals, `.neq(…"live_grounding")`). The `holdout` column is GENERATED ALWAYS (deterministic ~15% md5 hash of question_text+instrument) so liveGround cannot force it false — "Safety is enforced instead by the exclusion filters" (live_grounding.ts:528-533).
- `match_benchmark` (migration `20260726194320…sql`) retrieves only `holdout = false` rows, so a holdout question can never retrieve itself or any holdout seed as an anchor.
- Eval-window freeze: `_shared/eval_freeze.ts` — while any `heartbeat_runs.status='pending'` or `feature_flags.eval_window_freeze` is on, knowledge-writing jobs no-op (`inform-agents` checks it at the top) so `knowledge_rev` (row-count+mtime tag over benchmark_calibrations + knowledge_entries) stays fixed across paired eval runs.
- Future-event hygiene in ground-question: facts pairing a future date with an outcome verb are stripped (`filterFutureFacts` + `OUTCOME_VERB_RE` — the "Mbappé hat-trick for a match that hasn't happened" fix), and future-tense questions clamp baseline to ±0.6 (`FUTURE_BASELINE_CAP`).
- Market-scoring hygiene: immutable first-seen prior, pre-close backfill, annulled-market exclusion, abstention instead of 0.5.

Porous spots (present in code, stated plainly):
- Live-grounding seeds ARE in the retrieval corpus for everything else: `match_benchmark` explicitly whitelists them (`OR b.source_instrument = 'live_grounding'`) even when `p_include_low=false`. The gate/holdout evaluators score holdout seeds by calling ground-question, whose retrieval can therefore anchor on a web-derived live seed; exclusion happens only at the seed-pool level, not the retrieval level. At sim ≥ 0.95 PATH A waives the `confidence='high'` requirement ("Fix 1 — weakened confidence gate"), so a medium-confidence live seed can be blind-copied.
- `ground-question`'s "web grounding" (`webGroundFactsPolarized`) is NOT live: it calls Gemini-2.5-flash through the Lovable gateway with no search tool — the adversarial pro/con "facts" and their "source URLs" are parametric model recall dressed as retrieval. The genuinely live fetches on the answer path are current_context, market_anchor, and Path D only.
- The tool-less LLM baselines in predict-standing-cron/prediction-benchmark ("Reply with ONE decimal number") have no market blinding beyond not being shown the price in-prompt; the engine's own reading, meanwhile, records `market_prob_at_reading` alongside but does not feed the prior into the solve (the market enters only via the soft conformity anchor on the api-globe-ask door, not the standing-cron scoring path).
